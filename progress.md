# progress — rag-docs-demo

## Зачем

Вакансии Upwork по AI-автоматизации просят показать работающую RAG-систему.
В cycling-coach retrieval есть и измеряется (recall@3), но на Postgres
full-text, pgvector отложен. Это демо закрывает векторную половину и
показывает «RAG по-взрослому»: цитаты со страницами, eval, честный отказ,
стоимость запроса. Контекст поиска работы — `C:\Users\evgen\CVbank`.

## Решения (16.11.2026, обсуждены и приняты)

| Вопрос | Решение | Почему |
|---|---|---|
| Язык и обвязка | Python 3.12 + FastAPI, чистый Anthropic SDK, без LangChain/LlamaIndex | Клиенты RAG-вакансий читают Python; обвязка скрывает промпты и фрагменты. LangChain — ключевое слово в описании, «по запросу» |
| Эмбеддинги | Локальная open-source модель в контейнере, небольшая, английская | У Anthropic эмбеддингов нет; без второго ключа; аргумент «данные не уходят» для клиентов с self-hosted |
| Корпус | Заказы (PO) и счета в PDF, разные форматы, часть сканов, 20–50 документов, открытые | Самая частая боль в скане спроса (upwork-demand-ai-automation-2026-11-14.md) |
| Поиск | Гибрид: pgvector + full-text в Neon (уже есть у cycling-coach) | Одна база, без отдельного векторного сервиса |
| Генерация | Claude Opus 5.5, document-блоки с citations: cited_text + page_location; prompt caching системного промпта | Страница источника из коробки, отличие от шаблонов |
| Eval | 30–50 золотых вопросов; recall@k; доля ответов с опорой на цитаты; доля верных отказов вне корпуса | Главное отличие демо; таблица в README |
| Интерфейс | Одна веб-страница: вопрос, ответ с источниками, стоимость и время | Минимум; бэкенд channel-agnostic |
| Каналы | Telegram в демо не делаем; при надобности — WhatsApp Business Cloud API или Slack | Telegram на US/UK/EU-рынках почти не бизнес-канал |
| Хостинг | Azure Container Apps по образцу cycling-coach, minReplicas 0, бюджет monthly-5eur | Живая ссылка сильнее репозитория |
| Подача | Репозиторий github.com/ekotovqa + живая ссылка + видео 2 мин; карточка Project Catalog «RAG assistant over your documents with citations and an eval report» | Честно: демо для показа подхода, не «продакшен-RAG опыт» |
| Время | 3–4 вечера; при нехватке режем хостинг, оставляем репо + eval + видео | — |

## Порядок работы

1. Ингест и поиск без интерфейса: PDF → фрагменты со страницей → эмбеддинги → pgvector + full-text. Самая рискованная часть.
2. Eval-набор и замер recall@k; подбор размера фрагментов и модели эмбеддингов.
3. Генерация с цитатами и отказами; замер доли ответов с опорой на цитаты.
4. Веб-страница, стоимость и время запроса.
5. Dockerfile, Azure Container Apps, живая ссылка.
6. README с таблицей eval, видео, карточка каталога.

## Состояние на утро 17.11.2026

Сделано за ночь 16→17.11 (шаги 1–5 порядка работы, шаг 6 частично), 8 коммитов, ничего не запушено:

- **Корпус** (`src/ragdemo/corpus`): генератор 40 синтетических документов, 12 вымышленных поставщиков,
  6 макетов, 3 валюты, 4 формата чисел, 5 форматов дат, 21 двухстраничный, 14 сканов (поворот, шум,
  JPEG, без текстового слоя). `data/corpus/ground_truth.json` — точная истина для eval. PDF закоммичены
  (2,9 МБ), `.gitattributes` держит их бинарными.
- **Ингест** (`src/ragdemo/ingest`): текстовый слой через pypdfium2, OCR через RapidOCR (ONNX, без
  системных пакетов), восстановление пробелов в OCR-строках, чанки ≤900 символов с заголовком документа
  в каждом чанке. 61 страница (20 OCR) → 100 чанков за ~140 с.
- **Поиск** (`embed.py`, `store.py`, `retrieve.py`): bge-small-en-v1.5 через fastembed, pgvector +
  tsvector в одном SQL, лексика со взвешенными термами (номер документа 3, число 2, слово 1, общие
  слова 0.4), RRF k=60, буст за совпадение номера документа выше потолка RRF. Поиск ~120 мс.
- **Eval** (`src/ragdemo/eval`): 103 золотых вопроса из ground truth (93 с ответом, 10 без), детерминированные
  проверки (числа в обоих разделителях, варианты дат, подстроки), отчёт в `data/eval/latest-*.md`.
  **Retrieval: page recall@1 90%, @3 100%, на сканах 100%.** Путь к цифрам: 91% → 97% (пробелы в OCR)
  → 100% (ORDER BY в лексической CTE, буст 0.05 вместо 0.01). Все три дефекта нашёл eval.
- **Ответ** (`answer.py`, `pricing.py`): Claude Opus 5.5 через `client.beta.messages.create`, каждый чанк —
  document-блок с `citations`, `[n]` → файл/страница/цитата, протокол отказа `NOT_IN_DOCUMENTS`,
  `fallbacks="default"` с бетой server-side-fallback (включено по умолчанию, `RAGDEMO_FALLBACKS=false`
  выключает), стоимость по таблице цен, effort `medium`. **Вживую не проверено: нет ключа.**
- **Веб** (`src/ragdemo/web`): одна страница + JSON API, цитаты ссылками на PDF с `#page=N`, панель
  «почему эти чанки» с рангами, стоимость и время, отчёт eval и список документов; лимит 10 вопросов/мин
  на IP и дневной потолок $2 (в памяти процесса). Без ключа показывает найденные чанки и причину.
- **Docker** (`Dockerfile`, `docker-compose.yml`): образ 1,5 ГБ с моделями внутри, собран и проверен
  локально против контейнера Postgres (`ragdemo-pg`, порт 54329, пароль ragdemo — только для разработки).
- **Azure** (`infra/`, `.github/workflows/deploy.yml`): bicep в две стадии по образцу cycling-coach
  (identity, Key Vault, Log Analytics, env, app 1 vCPU/2 GiB, minReplicas 0, deploy-identity с OIDC),
  скрипт секретов, workflow tests → GHCR → `az containerapp update` → health. Компилируется, не применялось.
- **Тесты**: 68, все зелёные (`uv run pytest`), интеграционный тест стора на локальном Postgres.

**Что нужно от Евгения, чтобы двинуться дальше:**

1. Ключ Anthropic в `.env` (`ANTHROPIC_API_KEY=...`, файл в .gitignore). Тогда: `uv run ragdemo ask "..."`,
   `uv run ragdemo eval` (~$1, таблица ответов в README), проверка цитат на реальном ответе.
2. База Neon для облака: новая база в проекте cycling-coach или новый проект; строка подключения
   пойдёт в Key Vault через `infra/secrets-to-keyvault.ps1`.
3. Решение о публикации: `gh repo create ekotovqa/rag-docs-demo --public` + push, затем Azure в две стадии
   (README, раздел Deploy). `infra/main.parameters.json`: подставить id репозитория в `deploySubject`.

**Замечено, не сделано:**

- На одном скане (FV-2025-0219, макет «nordic») детектор RapidOCR склеил три строки таблицы в одну
  («MT-TAP-M8 MT-END-10 MT-DRL-SET … 24 5 1 58,90 34,20 12,60»). Поиск это не ломает, точность ответов
  по позициям на сканах может просесть. Крутить `det_unclip_ratio`/DPI или группировать по словам.
- OCR читает `68.30` как `68:30`, `Brno` как `Brmo`. Для чисел можно добавить нормализацию `:`→`.` в
  числовых токенах.
- Prompt caching системного промпта не сработает: промпт короче минимального префикса модели. В README
  сказано честно.
- Образ 1,5 ГБ из-за onnxruntime + opencv (RapidOCR). Не критично для Container Apps.
- Межд документные вопросы («какие ещё счета от того же поставщика») — один прыжок поиска, буст номера
  перетягивает на сам документ. Записано в README как ограничение.
